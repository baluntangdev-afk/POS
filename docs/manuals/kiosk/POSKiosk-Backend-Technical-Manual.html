1. Architecture

NestJS (TypeScript) REST API over PostgreSQL, using TypeORM. One process, deployed either via Docker (dev) or as a Node SEA Windows service (production installer).

1.1 Module layout

Each domain lives under be/src/<domain>/:

products/
  dto/            input/output DTOs (class-validator)
  entities/       TypeORM entities
  mapper/         entity <-> DTO mappers (pure static classes)
  services/       one file per use-case (CreateProductService, ...)
  products.controller.ts
  products.service.ts   orchestrates the feature services
  products.module.ts

1.2 Cross-cutting

ConcernMechanism
AuthJWT via Passport. Global JWT guard; @Public() opts out. @CurrentUser() injects identity. Role guards: @RequireAdminOrSupervisor(), AdminOrSupervisorGuard, @RequireAdminOrSupervisorOrSelf('id').
EventsEventEmitterModule (in-process).
SchedulingScheduleModule + CronJobsModule.
Validationclass-validator / class-transformer on DTOs, global ValidationPipe.
API docsSwagger at /api/docs.
Global prefixapi/v1 (health also mounted under it).

1.3 Data access rules

  • TypeORM with PostgreSQL. Never synchronize: true.
  • Schema changes only via migrations in src/database/migrations/ (timestamp-named).
  • src/database/migrations/index.ts must stay in sync — npm run migration:sync-index (also run automatically by build:sea).
  • Seeders in src/database/seeders/; their index is likewise synced.

10. Device transfer internals

src/device-transfer/. Endpoints (admin/supervisor only):

MethodPathSummary
POST/api/v1/device-transfer/exportExport the full public schema as one gzipped-then-AES-256-GCM-encrypted .posbackup
POST/api/v1/device-transfer/importReplace the full dataset from a .posbackup (destructive)
  • Export includes every base table plus the migrations table.
  • Import runs in one transaction: SET LOCAL session_replication_role='replica' (needs a superuser DB role — true for the bundled Postgres), TRUNCATE … CASCADE, bulk re-insert preserving primary keys, then reset every sequence (parsed from column_default, so standalone sequences like z_readings_z_counter_seq are covered).
  • A strict import is refused unless the archive's migration history is identical to the target's.
  • partialRestore: 'true' skips the migration gate, keeps the target's own migrations table, and imports only tables/columns present on both devices; a table is dropped whole if the target added a required column the archive lacks, a column is dropped if its Postgres udt changed. Everything skipped is returned in DeviceImportSummaryDto.skipped ({ tables, columns }).
Note  See docs/runbooks/kiosk-device-migration.md for the operational procedure.

11. Migrations & schema

  1. Change an entity.
  2. npm run migration:generate (diff-based) or npm run migration:create (blank), name it with a timestamp.
  3. Review the generated SQL. Migrations are the only way the schema changes.
  4. npm run migration:up to apply; npm run migration:show to check status; npm run migration:down reverts the last one.
  5. npm run migration:sync-index to refresh migrations/index.ts (build:sea does this automatically).

Notable migrations

MigrationEffect
1779582000000products.image_url BYTEA→TEXT; adds price, is_available, sort_order, category; creates product_modifier_groups junction
1779582100000Drops the catalog_-prefixed tables; kiosk now reads via /catalog/products + /products/:id

The installer runs all migrations (79 at time of writing) on first install and again via POSBackend.exe --migrate during recovery.

12. Production build & Windows installer

13.1 Backend SEA

cd be
npm install
npm run build:sea      # sync indexes -> nest build -> @vercel/ncc bundle
                       # -> SEA blob -> inject into node -> be\POSBackend.exe

Output be\POSBackend.exe (~80–120 MB). Build machine needs Node 22 LTS.

13.2 Full installer

# repo root, prompts for version:
.\build-installer.bat
# 1 verify prereqs (Inno Setup 6, C:\pgsql, C:\nssm, be\.env.prod)
# 2 optionally bump #define MyAppVersion in installer.iss
# 3 flutter codegen (pub get + build_runner)
# 4 parallel: npm run build:sea  +  fvm flutter build windows
# 5 auto-strip curly quotes from installer.iss
# 6 compile with ISCC.exe
# -> be\installer\output\POSKiosk-Setup-<version>.exe

13.3 What the installer does on the target

StepAction
0Silently installs VC++ 2015–2022 redistributable
1Extracts to C:\POSKiosk\
2–5Inits PostgreSQL data dir C:\posdata\, configures postgresql.conf, grants NT AUTHORITY\NetworkService, registers + starts POSPostgres
6–7Waits for Postgres, creates pos_db
8–9Runs all TypeORM migrations; optionally seeds
10Installs POSBackendService via NSSM (auto-start)
11Writes C:\POSKiosk\settings.txt with the wizard's kiosk number
Important  Install paths contain no spaces on purpose — pg_ctl cannot register a service whose binary path has spaces. Never edit installer.iss in an editor with smart-quote autocorrect; use npm run check:quotes / fix:quotes.

13. Verification & troubleshooting

Verify an install (elevated PowerShell on the target)

Get-Service POSPostgres, POSBackendService | Format-Table Name, Status
& "C:\POSKiosk\pgsql\bin\pg_isready.exe" -h 127.0.0.1 -p 5432
Invoke-WebRequest http://localhost:3000/api/v1/health -UseBasicParsing   # 401 = endpoint up, auth active
Get-Content "C:\POSKiosk\settings.txt"                                   # kiosk.no=<n>

Common issues

SymptomFix
App: “no internet connection”Check both services Running; pg_isready; tail setup-postgres-install.log and backend-error.log.

Missing tables / 42P01Migrations didn't run: Set-Location C:\POSKiosk\backend; .\POSBackend.exe --migrate; Restart-Service POSBackendService.
