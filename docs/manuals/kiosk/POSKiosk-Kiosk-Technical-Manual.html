1. Overview & architecture

The kiosk is a Flutter desktop application targeting Windows (Android is also buildable). It is a thin client: all business logic and persistence live in the NestJS backend.

1.1 Stack

ConcernChoice
UI toolkitFlutter (Dart ^3.7.2), pinned via FVM (.fvmrc)
State managementHooks Riverpod (hooks_riverpod + flutter_hooks)
NavigationGoRouter with typed routes (go_router_builder codegen)
Serializationdart_mappable (*.mapper.dart)
HTTPDio, with an auth interceptor
Configenvied (compile-time env, env.g.dart)
Windows integrationwindow_manager, win32, screen_retriever, desktop_multi_window
Printingesc_pos_utils_plus (ESC/POS receipts)
Assetsflutter_gen (lib/gen/assets.gen.dart)

1.2 Data flow

View (HookConsumerWidget)
  -> Riverpod provider (state/)
    -> Repository (repositories/)
      -> API source (lib/data/backend_api/sources/)
        -> Dio client (api_clients.dart, auth interceptor)
          -> Backend  http://<host>:3000/api/v1

1.3 Feature module layout

lib/features/<feature>/
  entities/       immutable domain models + .mapper.dart
  repositories/   abstract interface + Impl calling the API layer
  state/          Riverpod AsyncNotifier / StateNotifier providers
  use_cases/      (optional) single-responsibility operations
  view/           screens & dialogs (HookConsumerWidget)

1.4 HTTP layer

lib/data/backend_api/
  sources/        one class per backend resource (ProductsApi, ...)
  schemas/        @MappableClass DTOs mirroring backend DTOs
  mappers/        custom dart_mappable type mappers
                  (ImageUrlMapper, DateTimeWithOffsetMapper, ...)
  api_clients.dart  Dio provider wired with the auth interceptor
Note  Clean-architecture rule: lib/data/ must never import lib/features/. Error translation (DioException → ApiException) belongs in the data layer.

3. Environment configuration

Copy kiosk/.env.sample to kiosk/.env and fill every value. Variables are read at compile time by envied, so you must re-run code generation after changing them.

VariablePurpose
BACKEND_API_BASE_URLBase URL of the NestJS API, including /api/v1 (e.g. http://localhost:3000/api/v1).
SECURE_STORAGE_KEYKey used to encrypt tokens in secure local storage.
ORDERS_LIVE_FEED_WS_URLWebSocket URL for the live channel-orders feed (Orders board).
CARTIVO_AUTH_API_BASE_URLBase URL for the external ordering-platform auth service.
ORDERS_EVENTS_API_BASE_URLBase URL for the channel-order events / history API.
CLIENT_IDClient identifier for the external orders integration.
WEBHOOK_SECRETShared secret used to verify inbound order webhooks.
Note  Every new variable must also be declared as an @EnviedField() on the Env class in lib/config/environment/, or the build will not see it.

4. Install, generate, run

4.1 First-time setup

cd kiosk
dart pub global activate fvm            # once per machine
fvm use stable                          # install the pinned Flutter
cp .env.sample .env                     # then edit .env
fvm flutter pub get
fvm dart run build_runner build --delete-conflicting-outputs

4.2 Run

fvm flutter run -d windows              # desktop
fvm flutter run -d android              # android (optional)

In dev mode main.dart sizes the window to 1536×864; in a release build it goes full-screen.

4.3 Analyze

fvm dart analyze
Note  For mobile-only work in the sibling mobile/ and mobile_merchant/ apps, verify with dart analyze and do not run or modify be/ or kiosk/.

8. Windows specifics

8.1 Fullscreen & DPI

  • main.dart initialises window_manager; production builds go borderless full-screen, dev builds use 1536×864.
  • win32 is used for high-DPI awareness.

8.2 Customer display second window

main.dart checks the window argument: the normal engine runs the cashier app, a second engine (desktop_multi_window) runs the customer display. screen_retriever finds the non-primary monitor (falling back to visible-position comparison when a display reports an empty id) and positions the window there without stealing focus. CustomerDisplayHost in the cashier engine pushes debounced snapshots to it.

8.3 On-screen keyboard

Text fields use KeyboardSuppress helpers plus a PhysicalKeyboardDetector so that a hardware keyboard, when attached, disables the touch keyboard automatically.

8.4 Printing

Receipts and X/Z/daily reports are encoded to ESC/POS byte streams (encode_esc_pos_* use cases) and also rendered to PDF (render_*_pdf) for preview / archive.

9. Building a release & packaging

9.1 Standalone Windows build

cd kiosk
fvm flutter build windows --release
# output: kiosk\build\windows\x64\runner\Release\
#   pos_app.exe, *.dll, data\

9.2 As part of the one-click installer

From the repo root, build-installer.bat runs Flutter codegen, then builds the Flutter app and the backend SEA in parallel, then compiles the Inno Setup installer. See the Backend — Technical Manual for the full installer walkthrough.

Installed componentLocationRuns as
Flutter app (pos_app.exe)C:\POSKiosk\Desktop app / autostart
Backend SEA (POSBackend.exe)C:\POSKiosk\backend\Service POSBackendService (NSSM)
PostgreSQL 16C:\POSKiosk\pgsql\Service POSPostgres
Note  Runtime kiosk identity on an installed machine comes from C:\POSKiosk\settings.txt (kiosk.no=<n>), written by the installer wizard — not from .env.

10. Troubleshooting

SymptomCause / fix
App stays on start-up screenHealth poll to /health/live failing. Check POSBackendService and POSPostgres are Running; check BACKEND_API_BASE_URL. On an installed machine run C:\POSKiosk\scripts\recover-services.bat as admin.
build_runner errors after a pullRun with --delete-conflicting-outputs; if still broken, fvm flutter clean && fvm flutter pub get then regenerate.
Env value not picked upIt was added to .env but not to the Env class, or codegen wasn't re-run.
Blank product grid vs. real errorThe grid distinguishes empty-category from load failure; a failure shows “Could not load products” with Retry — inspect the Dio error / token.
Customer display on wrong monitorEmpty display ids on some hardware; fix the Windows primary display or cabling and restart.
“Internal server error” creating a saleBackend can't resolve the kiosk number — verify settings.txt and restart the backend service.
